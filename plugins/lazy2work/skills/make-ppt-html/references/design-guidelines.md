| 본문 텍스트 | 30% | `slate-100`~`200` (**pure white 금지**) | `slate-800` (pure black보다 부드러움) |
| 보조 텍스트 | — | `slate-400` | `slate-500` |
| **강조 (단 1색)** | 10% | **`sky-400`** 또는 `amber-400` | **`blue-600`** 또는 `amber-600` |
| 시맨틱: 긍정 | — | `emerald-400` | `emerald-700` (텍스트) / `emerald-600` (보더) |
| 시맨틱: 부정 | — | `red-400` | `red-600` |

**본문 하한**: 24pt 상당 (Tailwind `text-2xl` 표준 / `text-xl` 하한). 제목 `text-4xl`+.

## 1. 색상

### 1.1 색상 5규칙 (이것만 지키면 90% 해결)
1. **60-30-10**: 중립 배경 60% + 본문·구조 30% + **강조 10%** — 강조색은 "가장 눈에 띄어야 할 단 하나"(핵심 키워드·결론 수치·CTA)에만 예약.
2. **총 색 수 ≤ 3~4** (무채색 제외). 색이 많은 것 = 미숙한 디자인의 가장 흔한 신호.
3. **대비 7:1 목표** (WCAG 본문 최소 4.5:1 — 프로젝션 시 인지 대비가 30% 떨어지므로 여유 필수). 최종 팔레트는 WebAIM Contrast Checker로 실제 크기에서 검증.
4. **적록 회피 + 이중 단서**: 빨강-초록으로 의미를 구분하지 않는다(관객 ~8%가 적록색약). 강조 = 색+굵기, 상태 = 색+아이콘(✓/✗) 병행.
5. **시맨틱 고정**: 덱 전체에서 초록=좋음 · 빨강=나쁨 · amber=주의 · 파랑=중립. **강조색은 빨강 계열 금지**(시맨틱과 충돌).

### 1.2 강조의 작동 원리 = 희소성
- 강조색은 **한 슬라이드에 1~2곳 이하**. 모든 곳이 강조면 아무것도 강조되지 않는다.
- 강조가 더 필요하면 색이 아니라 **굵기(`font-bold`)·크기·여백**으로.

### 1.3 차트·다이어그램 다색 (색맹 안전)
Okabe-Ito 8색을 Tailwind 임의값으로: 검정 `#000000` · 주황 `#E69F00` · 하늘 `#56B4E9` · 청록 `#009E73` · 노랑 `#F0E442` · 파랑 `#0072B2` · 주적 `#D55E00` · 분홍 `#CC79A7` (예: `text-[#E69F00]`).

### 1.4 다크/라이트 결정표

| 환경 | 선택 |
|---|---|
| 어두운 대형 홀·컨퍼런스 / 3,500+ lumens·LED 패널 | 다크 |
| 밝은 회의실 / 프로젝터 <2,000 lumens | 라이트 (저휘도는 강제) |
| 원격 화면 공유·문서 배포 겸용 / 모를 때 | 라이트 |

어느 쪽이든 **실제 발표 장비 리허설이 색상 선택보다 중요**하다.

## 2. 폰트 — 종류와 크기

### 2.1 시인성 좋은 폰트 (산세리프가 기본값 — 얇은 세리프 획은 프로젝터에서 소실)

| 용도 | 영문 | 한글 |
|---|---|---|
| **만능 기본** | Roboto · Open Sans · Lato · Source Sans | ★ **Pretendard** (국영문 혼용 곡선·자간 일관, 9굵기) |
| 원거리·저해상도 | Verdana (화면용 설계·큰 x-height) | Noto Sans KR (자간 넓음 — 보정 필요) |
| 제목·임팩트 | Montserrat | G마켓 산스 · LINE Seed (표지·대제목만) |
| 보수적 대안 | Segoe UI · Tahoma | 나눔스퀘어 네오 · KoPubWorld돋움 |

- **2폰트 제한**(제목+본문) 또는 **한 가족 2굵기 차**(Pretendard Bold 제목 + Regular 본문)가 가장 안전.
- 폰트는 **로컬 번들**(@fontsource 등) — 발표장 네트워크 의존 금지.

### 2.2 크기 공식과 환경별 본문 크기
> **최소 pt = 최대 시청 거리(m) × 2.5** (생리적 최소) → 편안한 가독은 **+20~30%**

| 환경 | 최원거리 | 본문 권장 |
|---|---|---|
| 소회의실 | 3~4m | 24~28pt |
| 표준 회의실 | 6~8m | 28~32pt |
| 대형 홀 | 10~12m | 32~40pt |
| 강당 | 15~20m | 44~54pt |

### 2.3 위계별 크기 + Tailwind 매핑 (reveal 기본 960×700 좌표계)

| 요소 | pt 가이드 | Tailwind 클래스 |
|---|---|---|
| 표지 제목 | 54pt+ | `text-6xl font-bold` |
| 슬라이드 제목(H1) | 40~48pt bold | `text-4xl`~`text-5xl font-bold` |
| 섹션 제목(H2) | 32~36pt | `text-3xl` (H1과 8pt+ 차이) |
| **본문** | **26~30pt · 24pt 하한** | `text-2xl` 표준 / `text-xl` 하한 |
| 캡션·라벨 | 20~24pt (20 미만 = 6m 밖 실독 불가) | `text-base`~`text-lg` |
| 각주·출처 | 18~20pt — 가급적 말미 References 슬라이드로 | `text-sm` (남용 금지) |
| 코드 | **본문보다 작게 금지** | `text-base` 하한 |
| 스탯 콜아웃 | 60~72pt | `text-7xl font-bold` |

- **24pt 하한의 근거**: 그 미만이면 관객이 "읽기 vs 듣기" 주의 분할에 빠진다 — 사람은 동시에 못 한다. 30pt로 안 들어가면 텍스트가 너무 많은 것.
- 정확한 체감 크기는 pt 환산보다 **투영 후 실측 리허설**.
- ⚠️ **weight 300(Light) 이하 금지**(투사 시 소실) · 한글 이탤릭 금지(굵기·색으로 강조) · 장식·손글씨 폰트는 표지 한 줄까지만.

## 3. 정보 중요도에 따른 배치와 강조

### 3.1 배치의 1원칙: 패턴이 아니라 위계
F/Z 시선 패턴은 **위계가 없을 때의 폴백 경로**일 뿐 — 시각 단서(크기·색·여백)가 있으면 그것이 시선을 지배한다. **보는 순서를 위계로 직접 설계하라.**
- 텍스트형 슬라이드 = F 가정 → 핵심을 **좌상단·각 행 첫머리**에.
- 타이틀·결론·단일 메시지 = Z 가정 → **중앙 대형** + 우하단 마무리.

### 3.2 위계를 만드는 8레버 (중요도 순)

| # | 레버 | 적용 |
|---|---|---|
| 1 | **크기** | 가장 중요한 주장/수치를 가장 크게 — 60~72pt 스탯 콜아웃 |
| 2 | 색·대비 | 강조색은 핵심에만, 보조는 muted |
| 3 | 타이포 위계 | H1/H2/본문 일관 단계 (§2.3) |
| 4 | 근접 | 관련 요소는 붙이고 무관한 것은 띄운다 |
| 5 | 정렬·그리드 | 소수의 수직 기준선 — `grid grid-cols-N gap-8` |
| 6 | 여백 | 핵심 주변에 더 많은 빈 공간 |
| 7 | 위치 | 결정적 내용은 상단/좌측/중앙 |
| 8 | 반복 | 같은 유형 슬라이드 = 같은 레이아웃 |

### 3.3 중요도 → 크기·강조 방법 매핑

| 중요도 | 크기 | 강조 방법 |
|---|---|---|
| 슬라이드의 결론 (주인공 1개) | 가장 크게 (`text-4xl`+ 또는 스탯 `text-7xl`) | 강조색 + `font-bold` (이중 단서) |
| 핵심 근거·키워드 | 본문 크기 | 본문색 + `font-bold` 또는 강조색 1~2곳 |
| 일반 본문 | `text-2xl` | 본문색, 강조 없음 |
| 보조·메타 정보 | `text-lg` 이하 | 보조색 (`slate-400/500`) — 시각적으로 물러남 |

### 3.4 배치 수칙
1. **슬라이드당 주인공 1개** — 가장 큰 요소가 곧 그 슬라이드의 결론.
2. 본문은 **좌측 정렬** (`text-left`) — 중앙 정렬은 제목·단일 메시지에만.
3. 넓고 빽빽한 문단 금지 — 둘째 줄부터 점점 덜 읽힌다.
4. 읽기 순서가 모호하면(4분면 동급 카드 등) 번호·화살표·크기 차로 순서를 명시.

## 4. 정보 종류에 따른 페이지 구성

### 4.1 기본형: Assertion-Evidence (실증 우월 구조)
**제목 = 주장 문장, 본문 = 그 증거 1개.**
- ❌ 주제어 제목: "벡터 검색 성능" + 불릿 7개
- ✅ 주장 제목: **"BBQ 양자화는 메모리를 95% 줄인다"** + 차트 1개
- 상세 수치·출처·부연은 `<aside class="notes">`(발표자 노트, 본문의 3~5배 분량)로.

### 4.2 구성에 직결되는 Mayer 원칙 6개
텍스트→비주얼 교체(multimedia) · 무관 요소 제거(coherence) · 중요한 것에 신호(signaling) · 낭독할 문장을 그대로 쓰지 않기(redundancy) · 라벨은 그림 바로 옆(spatial contiguity) · 한 번에 한 덩어리(segmenting).

### 4.3 정보 유형 → 레이아웃 매핑

| 정보 유형 | 레이아웃 | 핵심 규칙 | Tailwind 골격 |
|---|---|---|---|
| 단일 주장·결론·인용 | 중앙 대형 | 강조 1곳, 여백 최대 | 중앙 정렬 + `text-5xl` |
| 비교 (A vs B) | 좌우 대칭 2분할 | **동일 구조·동일 크기**, 차이점만 강조색 | `grid grid-cols-2 gap-8` |
| 프로세스·타임라인 | 가로 플로우 | 단계 ≤5, 번호+화살표. **시간 차원 없으면 타임라인 금지** | flex 행 + `→` |
| 데이터·차트 | 차트 1개 + 주장 헤드라인 | **1슬라이드 1차트 1메시지** · 직접 라벨링(범례 금지) · 핵심 시리즈만 강조색 · 3D/chartjunk 제거 | `.stretch` |
| 목록·기능 | 아이콘+행 | **≤4 불릿** — 초과 시 분할 또는 카드 그리드 | `space-y-4` / `grid` |
| 정확한 수치 대조 | 표 | 표는 정확값 비교에만 — 추세는 차트로. 구분선은 옅게 | `border-b border-slate-200/700` |
| 섹션 전환 | 디바이더 | 큰 제목만 — 배경색 교차로 리듬 | `data-background-color` 교차 |
| 상세·부록 | vertical 슬라이드 | 메인 흐름은 가로 일직선 유지 | 중첩 `<section>` |

## 5. 이미지 — 크기와 배치

### 5.1 크기
- **"하나의 크고 강력한 이미지"** — 여러 작은 이미지 나열보다 항상 낫다. 기본형 = **full-bleed 배경 + 여백에 텍스트 오버레이**.
- 예외는 비교(Before/After)만 — side-by-side를 **동일 크기·동일 정렬**로.
- **해상도**: 원본 100% 초과 확대 금지. full-bleed는 1920×1080px 이상. 비율 왜곡 금지 — crop으로 맞춘다.

### 5.2 배치
- **Rule of Thirds**: 3×3 그리드의 선/교점에 초점(인물의 눈·제품)을 배치 — 정중앙은 정적.
- **1/3 : 2/3 비대칭 분할**이 기본(이미지 2/3 + 텍스트 1/3 또는 역) — 1/2:1/2 양분보다 위계가 생긴다.
- **인물 시선은 콘텐츠를 향하게**(gaze cueing): 시선·몸 방향이 핵심 텍스트/차트 쪽을 보게 배치. 화면 밖을 보면 관객 주의도 샌다. (인물 우측 1/3 + 좌측 텍스트를 바라보는 구도)

### 5.3 reveal.js 적용
```html
<!-- full-bleed 배경 + 대비 확보용 오버레이 -->
<section data-background-image="img/hero.jpg" data-background-opacity="0.35"
         data-background-color="#0f172a">
  <h2 class="text-5xl font-bold text-slate-100">주장 문장 헤드라인</h2>
</section>

<!-- 콘텐츠 내 이미지: 슬라이드 채우기 (직계 자식 1개만 가능) -->
<img class="stretch" src="img/chart.png" alt="결과 차트">
```
- 텍스트를 이미지 위에 얹을 땐 어두운 오버레이/스크림으로 **대비 7:1 확보**.
- 라벨·설명은 이미지 **바로 옆에**(spatial contiguity) — 범례·각주로 분리 금지.
- 이미지가 내용을 대표하면 **텍스트 없이 이미지만** — 더 강하게 기억된다.
- 대형 미디어는 `data-src`(lazy) + 압축. 배포용이면 `alt` 필수.

## 6. reveal.js 기술 주의점

### 6.1 스케일링 모델 (최대 오해 지점)
- reveal은 **960×700 고정 좌표계**를 `transform: scale`로 통째로 확대/축소한다.
- → **vh/vw·% 높이·`md:` 반응형 prefix 무효.** 고정 캔버스에 절대적으로 디자인하고 화면 대응은 scale에 맡긴다.
- 넘치는 텍스트 `r-fit-text` · 겹침 `r-stack` · 가로 배열 `r-hstack` · 직접 제어는 `disableLayout: true`(모든 화면 대응을 직접 책임).

### 6.2 Tailwind 통합 = 전략 A (권장)
- **내장 테마를 버리고**(reset.css + reveal.css만 로드) 모든 타이포·색을 유틸 클래스로, 배경은 `data-background-color`로 → Preflight 충돌 원천 제거.
- 보정 2줄 필수: ① reveal reset이 border-style을 none으로 덮음 → `.reveal .slides *, ...::before, ...::after { border-style: solid; }` ② 테마 부재 시 UI 크롬(슬라이드 번호·진행바·컨트롤) 색을 배경에 맞게 지정.
- 코드 하이라이트 테마(monokai.css 등)는 별도 유지.
- **Play CDN은 프로토타입까지만** — 발표·배포는 빌드로 (발표장 와이파이에 덱의 생사를 걸지 마라).

### 6.3 PDF 내보내기 (조기·반복 테스트 — 마지막에 하면 반드시 깨진다)
- `?print-pdf` → Chrome 인쇄 → Landscape + 여백 없음 + 배경 그래픽 ON. **Chrome 전용**.
- 설정: `pdfMaxPagesPerSlide: 1` · `pdfSeparateFragments: false` · 배포용 `showNotes: 'separate-page'`.
- 덱 1/3 시점과 완성 직전 최소 2회 테스트. CLI 자동화는 decktape.

### 6.4 운영 수칙
`hash: true`(슬라이드별 URL) · `slideNumber: 'c/t'` · speaker notes 3~5배 분량+타이밍(S 키) · 코드 `data-trim data-line-numbers` 진행형 `|1-3|5` · 버전 고정+발표 전 git tag(직전 의존성 업데이트 금물) · overview(`ESC`)로 흐름 점검.

## 7. 하지 말아야 할 것 (통합 금지 목록)

**색상 ❌**
- 4색 초과 팔레트 · 슬라이드마다 다른 색
- pure white on pure black 풀 대비 장시간 (→ off-white on midnight)
- 색만으로 의미 전달 (적록 구분 등 — 색+아이콘/굵기 병행)
- 강조색을 빨강 계열로 (시맨틱 충돌)

**텍스트·폰트 ❌**
- 본문 24pt 미만 · 캡션 20pt 미만 · 코드 폰트를 본문보다 작게
- weight 300 이하 투사 · 한글 기울임 강조 · 3폰트 이상
- 텍스트 벽 (긴 문단·6+ 불릿) · 본문 중앙 정렬
- 발표자가 낭독할 문장을 슬라이드에 그대로 (redundancy)

**구성·레이아웃 ❌**
- 주제어 제목("성능 분석") + 불릿 나열 (→ 주장 문장 + 증거 1개)
- vh/vw·반응형 prefix 레이아웃 (스케일 모델 충돌)
- 깊은 vertical 중첩 미로 · 시간 차원 없는 타임라인
- 범례 의존 차트 · 3D 차트 · chartjunk
- inline `style=` 속성 · `.slide1` 식 슬라이드별 클래스

**이미지 ❌**
- 여러 장의 작은 이미지 나열 · 저해상도 확대 · 비율 왜곡
- 내용 무관 장식 이미지 (학습을 깎는다) · 워터마크 · 클립아트·진부한 스톡
- 대비 확보 없이 텍스트 위에 이미지 · 시선이 화면 밖을 보는 인물 사진

**효과·운영 ❌**
- 목적 없는 zoom·애니메이션 ("멋있어서"는 목적 아님)
- 모든 항목 fragment (클릭 피로)
- CDN 의존 배포 · 발표 직전 의존성 업데이트
